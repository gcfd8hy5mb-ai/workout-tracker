# LIFTOVA bug sweep — 2026-09-28

Scope: post-PR #81 production code audit after iOS Progress/History freezes.

High-confidence findings being addressed on the bug-sweep branch:

- Remaining document-wide MutationObservers in workout and profile presentation layers can create repeated expensive DOM scans on iOS.
- LIFTOVA presentation modules other than polish are served cache-first by the service worker and several loader URLs are unversioned, so installed/PWA clients can retain stale fixes.
- Repeated Supabase signup can still show “check your email” instead of telling the user that the email already has an account.
- Static index metadata still contains legacy PRISM title/icon values before runtime polish executes.

Automated post-merge PRISM Tests, Test and Deploy to GitHub Pages, and Pages deployment all passed for main commit 31be6054b8ce4a2a44cf07d442fcafef54e741af. The audit above targets runtime/iOS behavior that those static/unit checks do not exercise.
